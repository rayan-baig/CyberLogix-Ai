API reference

Every endpoint a customer or a developer can call: what it does, the credential it needs, its parameters and an example body. Read from the running service, version %%VERSION%%, so it lists what this server actually answers: %%ROUTE_COUNT%% endpoints.

Before you start

Every address below is relative to %%BASE_URL%%. Send and expect JSON. Most endpoints take one of these credentials, in a header:

  • Business API key, X-CyberLogix-Key: made when the business signs up, and replaced from the console's Setup tab. It acts for the whole business; keep it on a server.
  • Signed-in session, Authorization: Bearer $TOKEN: what POST /api/accounts/login returns. It acts as one person, with that person's role.
  • Sensor key, X-CyberLogix-Sensor-Key: one sensor's own key. It can only send that sensor's readings.
  • Partner key, X-CyberLogix-Partner: a reseller's key for its own book of accounts.

Some actions also need a role (owner, operator) as well as a credential; a request without it is answered 403 and says which. A body that does not fit is answered 422, naming the field. The examples use $KEY and $TOKEN for your own values: no real key is ever shown here.

Prefer an interactive explorer? Swagger UI and ReDoc show the same schema, loaded from a public CDN. The raw schema is at /openapi.json.
